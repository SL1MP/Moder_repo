## Коротко

Сервис самостоятельной модерации пакетов: разработчик заводит заявку, конвейер из девяти
шагов проверяет пакет, роли согласуют спорное, одобренное публикуется во внутренний
репозиторий. Задача этапа — **перенести backend с Python на Go**; перенос не закончен, но
всё, чем пользуются люди изо дня в день, уже работает на Go.

| | |

| Осталось на Python | админка и «Настройка», GitLab, три маршрута, часть CLI |

| Python-код | остаётся рабочим, 294 теста |
| Миграции | 12 (golang-migrate) + 7 (alembic), парные |

## Что сделано

### Конвейер и заявки (полностью на Go)

Девять шагов `db_check → blacklist → quarantine → license → download → vuln_scan →
banner_scan → sast_scan → publish`, очередь на Postgres (`FOR UPDATE SKIP LOCKED` +
`LISTEN/NOTIFY`), сторож зависших пакетов, повторы упавших прогонов, возобновление с нужного
шага после решения роли.

Заявки: создание тремя способами (перечисление, файл зависимостей, файл из GitLab), разбор
`requirements*.txt`, `poetry.lock`, `pyproject.toml`, `package-lock.json`, `yarn.lock`,
`package.json`, `go.mod`, `go.sum`, `packages.lock.json`, `packages.config`, `*.csproj`;
идемпотентность по `Idempotency-Key`; закрытие заявки автором.

### Решения ролей

Карантин, вердикт DevSecOps, вердикт юриста, заявление лицензии. Главное в этой части —
**распространение на siblings**: решение выносится по версии пакета, а не по заявке, и
доходит до всех, кто эту версию заказал. Без этого одинаковый пакет в чужой заявке висел бы
заблокированным навсегда.

### Проверки содержимого и отчёты

YARA (политический контент) и semgrep (SAST) через внешние CLI, безопасная распаковка
артефакта (zip-slip, символические ссылки, архивные бомбы), отчёт по каждому прогону в JSON и
самодостаточном HTML, хранение в S3-совместимом хранилище, выдача через API и просмотр в
карточке.

SAST — **информационный шаг**: находки показываются и лежат в отчёте, но публикацию не
держат. Сканирование на политический контент публикацию держит.

### Транзитивные зависимости

Раскрытие дерева по данным реестров: `requires_dist` у pypi, packument у npm, `go.mod` через
прокси, `nuspec` у nuget. Каждое требование приводится к точной версии по правилам своей
экосистемы (semver, PEP 440, интервалы NuGet, MVS у Go), найденное заводится отдельным
пакетом заявки со ссылкой на родителя. `POST /api/v1/dependencies/resolve` показывает дерево
**до** создания заявки.

Три вещи говорятся вслух, потому что они про то, чего в дереве нет: обрезка по пределу,
нераскрытые зависимости, конфликты версий.

### Артефактори

Две реализации: **Nexus 3** (компонентный REST API) и **Artifactory** и совместимые (`PUT` по
адресу файла), выбор — `ARTIFACT_STORE`. Плюс снятие пакета с публикации (нужно для отзыва).

### Регламентные задачи

Работают внутри `worker-go`, расписание то же, что у celery beat:

| Задача | Как часто | Что было без неё |
|---|---|---|
| снятие истёкшего карантина | 15 мин | пакет стоял «в карантине до даты» вечно |
| уборка временного хранилища | 2 часа | карантинная зона росла, пока есть место |
| загрузка снапшота OSV | 6 часов | «база устарела», каждый пакет к DevSecOps вручную |
| перепроверка одобренных | после новой базы | уязвимость, найденная после одобрения, оставалась незамеченной |

Разово — `moderation maintenance [--quarantine|--cleanup|--osv-sync|--rescan]`.

### Вход

OIDC/Keycloak (Authorization Code + PKCE), локальный вход для сервисных учёток, роли из групп
каталога, RBAC на маршрутах.

### Интерфейс

Русскоязычный SPA (~4 400 строк): заведение пакетов четырьмя способами, дерево зависимостей и
его предпросмотр, карточка заявки с конвейером и отчётами, очереди DevSecOps и юристов,
обсуждения, база пакетов, профиль, настройка.

### Стенд и эксплуатация

`docker compose` со всем стеком, профили `sso` и `nexus`, оверлеи для SeaweedFS и внешнего
S3, инструкция локального запуска (`local-setup.md`) с разбором типовых поломок, команда
`moderation schema` — сверка схемы базы с кодом.

## Проблемы и что с ними стало

Все перечисленные всплыли на живом стенде или на проверке. Каждая исправлена; в скобках —
коммит.

| Что видел пользователь | В чём было дело | Итог |
|---|---|---|
| «Найдено уязвимостей: 0», а в отчёте 4 находки | счётчик заполнялся до проверки того, отработал ли сканер вообще | считаем только по отработавшему прогону, «сканер не отработал» — отдельное состояние (`addda58`) |
| SAST держал публикацию | шаг был блокирующим | шаг стал информационным, появился результат `info`, старые записи нормализованы миграцией (`addda58`) |
| SAST вообще не запускался | `semgrep-core` падал от **пустой** переменной `HTTP_PROXY`, которую подставлял compose | пустые прокси-переменные вычищаются перед запуском сканера (`44c49f1`) |
| «Заявка не закрыта», «Решение не применено» | в базе не было миграции 0008 — сервис писал в несуществующие столбцы | ошибки схемы теперь называют себя и говорят, какую миграцию накатить; появилась команда `moderation schema`; go-миграции сделаны безопасно повторяемыми (`eb7eb31`, `70655d4`) |
| Отчёт не открывался: «Не передан Bearer-токен» | отчёт открывался обычной ссылкой, а браузер не шлёт заголовок авторизации по `<a href>` | отчёт запрашивается с токеном и показывается в изолированном `iframe` (`7b13d1d`) |
| Пакет «в очереди», но никто его не берёт | воркер мог не подобрать пакет, и это ничем не лечилось | сторож очереди внутри `api-go` забирает залежавшиеся пакеты и громко пишет о каждом (`6d99f43`) |
| `pull access denied for minio/minio` | образ MinIO больше не отдаётся с Docker Hub анонимно | разобрано в `local-setup.md`, добавлены оверлеи SeaweedFS и внешнего (в том числе сертифицированного) S3 (`ec2081d`, `4d1dd05`, `379e622`) |
| «Не удалось получить конфигурацию OIDC-издателя» | сообщение не отличало «Keycloak не поднят» от «realm назван иначе» | сообщение называет адрес, код ответа и следующий шаг; в документации — разбор всех трёх случаев (`77f2c68`) |
| «Артефактори отклонил публикацию (405)» на каждом пакете | в go-версию попала только реализация для Artifactory, а стенд работает на Nexus: на `PUT` он отвечает 405 | перенесена вторая реализация, тип выбирается `ARTIFACT_STORE` и проверяется на старте; коды 401/403/404/405 объясняют себя (`f6e241a`) |
| Заявка по `poetry.lock` приезжала пустой | формат не различает прямые и транзитивные записи, все считались транзитивными и отбрасывались фильтром | такие файлы принимаются целиком с предупреждением — как уже было сделано для `go.sum`; исправлено и в python-версии (`0780855`) |
| Очереди ролей отвечали 500 | **своя регрессия**: в SQL-запрос добавили столбцы, в разбор строки — нет | поймано тестами очередей до стенда, исправлено (`e2c9898`) |

Отдельно — две вещи, которые выглядели как поломка, но поломкой не были: пакет в карантине
до даты (штатно, лечится регламентной задачей) и «база уязвимостей устарела» (снапшот ни разу
не загружали; теперь воркер забирает его сам).

## Что осталось на Python

Контейнеры `api`, `worker`, `beat` пока нужны.

**Маршруты.** `/admin/audit`, `/admin/osv-sync`, `/admin/osv-versions`, `/admin/reload`,
`/admin/queue-sweep`, `/settings`, `/settings/policies`, `/system/status` (экран «Настройка» и
журнал аудита); `/gitlab/*` (подключение GitLab и заведение заявки из файла в репозитории);
`POST /packages/check` (вкладка «Найти пакет»); `POST /packages/{id}/revoke`;
`POST /items/{id}/license-claim`.

**CLI.** `bootstrap` (миграции, realm Keycloak, бакеты, репозитории Nexus, демо-данные),
`create-service-account`, `import-package-list`, `reload-policies`, `queue-doctor`.

**Служебное.**

* ограничение частоты запросов (`RATE_LIMIT_REQUESTS_PER_MINUTE` go-версией игнорируется);
* бизнес-метрики Prometheus (`pipeline_step_total`, `worker_alive`, `pipeline_stuck_items`,
  `osv_index_age_days`, состояние circuit breaker) — go-версия отдаёт только стандартные
  коллекторы рантайма;
* повторы отдельных запросов к реестрам и circuit breaker: в Go повторяется весь прогон
  пакета целиком, отдельный запрос при 502 — нет.

## Долги и риски

Перечислено то, что известно и пока не сделано. Замалчивать такое дороже, чем признать.

1. **Стенд открыт наружу с паролями по умолчанию.** Postgres, Redis, MinIO и Keycloak
   слушают `0.0.0.0`, пароли — из `.env.example`. Для локальной машины терпимо, дальше нет.
2. **Шесть пакетных менеджеров не реализованы**: docker, general, maven, terraform,
   luarocks, conan. Это обязательный скоуп, не бэклог (`ci-parity-gaps.md`), Docker первым.
3. **`golang-migrate` не подключён в compose** — go-набор миграций накатывается вручную.
   Именно отсюда выросли два разбора «кнопка не работает».
4. **Нет перезагрузки политик без рестарта** в Go (в Python есть `POST /admin/reload`).
5. **Модель публикации в Artifactory не проверена на бою**: CI-версия публикует
   server-side copy'ем внутри Artifactory, go-версия — скачиванием и `PUT`. Разрешает ли это
   боевой инстанс — неизвестно; `ARTIFACT_DRY_RUN=true` существует ровно для этой проверки.
6. **Нет SBOM (CycloneDX)** — в CI-версии он генерируется по каждому диффу.
7. **Sandbox для `banner_scan` отсутствует**: проверка идёт локальными YARA-правилами.
8. **Конфликты версий транзитивных зависимостей не разрешаются** — обе версии попадают в
   заявку и помечаются конфликтом. Выбирать за разработчика сервис не вправе.
9. **Маркеры окружения** (`python_version < "3.8"`) не вычисляются: раскрывается лишнее.
   Промодерировать лишний пакет дешевле, чем пропустить нужный.
10. **`dry_run` в свёртке статусов python-версии** не выставляется — известное расхождение с
    go-версией.

## План

Порядок — по тому, сколько каждый шаг снимает с людей, а не по объёму кода.

### 1. Убрать Python из повседневной работы

1. Три коротких маршрута: `POST /packages/check`, `POST /packages/{id}/revoke` (код отзыва
   уже перенесён вместе с перепроверкой — остался обработчик), `POST /items/{id}/license-claim`.
   После них SPA почти перестанет ходить в Python.
2. Админка и «Настройка»: `/settings*`, `/system/status`, `/admin/*`. Самый крупный кусок, но
   обособленный.
3. GitLab: OAuth, хранение токенов, чтение файла. Последним — трогает шифрование токенов, а
   пользуется им меньшинство.
4. Остаток CLI (`bootstrap` в первую очередь) — после этого `api`, `worker` и `beat` можно
   гасить.

### 2. Закрыть служебные пробелы

Ограничение частоты запросов, бизнес-метрики, повторы и circuit breaker на вызовах к
реестрам, `golang-migrate` в compose, перезагрузка политик без рестарта.

### 3. Пакетные менеджеры

Docker (приоритет: образы тяжёлые, и поиск уже одобренного экономит больше всего), затем
general, maven, terraform, luarocks, conan. Каждому нужна миграция, снимающая
`CHECK (manager IN (...))` на трёх таблицах.

### 4. Развитие

* SBOM по каждой заявке;
* sandbox для проверки на вредоносное содержимое;
* ретроспективная чистка заблокированных пакетов;
* закрытие стенда (сеть, пароли, секреты) перед выходом за пределы локальной машины.

## Как проверяем

Три приёма, которые уже несколько раз оправдались:

* **Мутационное тестирование.** После каждого набора тестов вносится поломка в код и
  проверяется, что тесты падают. Тест, который не падает на сломанном коде, не проверяет
  ничего. Так были найдены, например, повторное снятие карантина и молчащий кэш снапшота.
* **Живой стенд.** Postgres, настоящие реестры pypi и npm, реальные semgrep и YARA, интерфейс
  в настоящем браузере. Утверждения вида «работает» делаются только после такого прогона;
  всё, что проверить не удалось (например, поведение боевого Artifactory), помечено как
  непроверенное.
* **Дифференциальная проверка против эталона.** Там, где реализуются чужие правила, свои
  тесты проверяют понимание правил, а не сами правила. Схемы версий прогнаны против
  `packaging` и `semver`: 73 200 пар «требование/версия» по pypi и 2 185 500 по npm,
  расхождений нет — и эта же проверка нашла две настоящие ошибки.

Прогон тестов с базой — **только `go test -p 1 ./...`**: база одна на все пакеты, часть
тестов проверяет состояние сервиса целиком, и параллельный прогон ломает не код, а тест.
