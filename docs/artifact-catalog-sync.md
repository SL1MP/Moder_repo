# Синхронизация базы пакетов с внутренним артефактори

## Назначение

База пакетов сервиса должна показывать не только версии, опубликованные его
конвейером, но и пакеты, которые уже находились в доверенных корпоративных
moderated-репозиториях до запуска сервиса или были добавлены туда вручную.

Синхронизация является импортом каталога, а не дополнительной стадией
модерации. Наличие версии в явно выбранном доверенном репозитории означает,
что она уже разрешена корпоративным процессом. Такая версия появляется в
обычной базе пакетов со статусом `approved`, файлами, контрольными суммами и
ссылками на внутренний артефактори. Отдельные статусы сверки пакету не
присваиваются.

## Источник истины и граница доверия

Доверенными считаются только целевые репозитории менеджеров из
`ARTIFACT_CATALOG_SYNC_MANAGERS`. Имя каждого репозитория берётся из
`ARTIFACT_REPO_<MANAGER>`. Staging, proxy и любые остальные репозитории
автоматически не обходятся.

Для корпоративного JFrog из текущего контура минимальная конфигурация:

```dotenv
ARTIFACT_STORE=generic
ARTIFACT_BASE_URL=https://artifactory.example.internal/artifactory
ARTIFACT_PUBLIC_BASE_URL=https://artifactory.example.internal/artifactory
ARTIFACT_AUTH_TYPE=bearer
ARTIFACT_TOKEN=<access-token>

ARTIFACT_REPO_PYPI=pypi-moderated
ARTIFACT_REPO_NPM=npm-moderated
ARTIFACT_REPO_GO=go-moderated
ARTIFACT_CATALOG_SYNC_MANAGERS=pypi,npm,go,nuget,conan,docker,luarocks,maven,php,terraform
MAINTENANCE_ENABLED=true
```

Эти значения можно задать на странице «Настройка». Секрет в браузер обратно
не передаётся. После сохранения runtime-конфигурация применяется штатным
механизмом web-настроек.

## Алгоритм

1. Администратор вручную ставит полный обход в очередь Postgres.
2. Для каждого выбранного менеджера читается файловый индекс его целевого
   репозитория.
3. Физический путь преобразуется в координаты `manager/name/version` без
   скачивания содержимого пакета.
4. Пакет, версия и все распознанные файлы идемпотентно добавляются или
   обновляются в базе.
5. Ссылки строятся на фактические файлы в артефактори. При отдаче API
   внутренний адрес заменяется на `ARTIFACT_PUBLIC_BASE_URL`.
6. Если та же версия ранее завершилась ошибкой в старой заявке, её элемент
   становится одобренным, а итоговый статус заявки пересчитывается. Закрытые
   пользователем заявки не изменяются.

Обход аддитивный. Если файл временно не попал в ответ JFrog из-за сети,
прав или неполного листинга, уже известная версия не удаляется и не
блокируется. Это исключает массовое исчезновение базы при временной ошибке
интеграции.

## Запуск и наблюдение

- кнопкой «синхронизировать сейчас» на странице «Настройка»;
- через API — `POST /api/v1/admin/artifact-catalog-sync` с ролью `admin`;
  тело `{ "managers": ["pypi", "npm", "go", "nuget", "conan", "docker", "luarocks", "maven", "php", "terraform"] }`
  позволяет выбрать менеджеры конкретного ручного запуска;
- через CLI — `moderation maintenance --catalog-sync`.

Перезапуск `worker-go` не создаёт новый запуск. Если вручную поставленная
задача уже имела статус `queued`, новый worker заберёт её из Postgres. Если
worker аварийно остановился во время обхода, зависший запуск закрывается как
ошибка и повторяется только по новому ручному запросу администратора.

HTTP-запрос только создаёт запись запуска и сразу отвечает `202`. Большой
первичный импорт продолжает worker в фоне, поэтому API и nginx не ждут его и
не получают 502. Состояние и счётчики доступны через
`GET /api/v1/artifact-catalog-sync` и в web-интерфейсе.

## Поддерживаемые раскладки

Импорт включается только для менеджеров, чью файловую раскладку сервис умеет
однозначно разобрать: PyPI, npm, Go modules, Maven, NuGet, Conan, Docker,
LuaRocks, Composer и Terraform. Для Maven применяются те же allow/deny-маски
файлов, что и при публикации: source/javadoc и checksum/signature
sidecar-файлы в каталог не добавляются.

Для Docker импортируются только теговые `manifest.json` и
`list.manifest.json`. Технические каталоги `sha256:*`, config и layers
пропускаются; версия сохраняется как `tag@sha256:<digest>`, чтобы ссылка и
последующее административное удаление относились к неизменяемому manifest.
Режимы `git` и `files` не участвуют в синхронизации: по их физическому пути
нельзя восстановить исходный URL и полную контрольную сумму без домыслов.

## Массовый первичный импорт

Содержимое wheel, tgz, zip и других пакетов при синхронизации не скачивается:
используются путь, размер, дата и SHA-256 из метаданных JFrog. Поэтому
существующую корпоративную базу не требуется повторно загружать через сервис.
Операция может идти долго из-за количества строк в БД, но не занимает очередь
проверок пакетов и не останавливает карантин, OSV или очистку staging.
