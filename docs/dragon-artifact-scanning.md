# Информационное сканирование Go-пакетов через Dragon

## Политика

Dragon применяется только к Go-модерации. После штатного скачивания Moder_repo
отправляет в Dragon тот же архив, который затем публикуется во внутренний
артефактори, сохраняет идентификатор запуска и ждёт его завершения.

Dragon не принимает решение о публикации:

- находки сканеров не блокируют пакет;
- ошибка отправки или ожидания не блокирует пакет;
- шаг не создаёт задачу или уведомление DevSecOps;
- результат шага сохраняется как информационный `info`;
- публикацию по-прежнему могут остановить другие обязательные проверки,
  например песочница или лицензия.

Для всех менеджеров, кроме `go`, шаг `dragon_scan` получает результат
`skipped`.

## Создание запуска

```http
POST /api/runs/archive?pipeline_id=<pipeline-id>&repository_id=<repository-id>
Authorization: Bearer <token>
Content-Type: multipart/form-data
```

Поля формы:

| Поле | Значение |
|---|---|
| `file` | архив Go-модуля из временного хранилища |
| `name` | имя Go-модуля, например `github.com/DataDog/zstd` |
| `label` | версия пакета, например `v1.5.7` |
| `publish` | значение `DRAGON_PUBLISH`, по умолчанию `true` |
| `priority` | значение `DRAGON_PRIORITY`, по умолчанию `4` |
| `variables` | ровно `{"SEC_AIE_PROJECT_LANGUAGE_GROUPS":"none"}` |

Поле `publish` относится к публикации результатов внутри Dragon/Oakshield и
не публикует пакет во внутренний артефактори. Пакет публикует только шаг
`publish` Moder_repo.

Пример настроек для подтверждённого контракта:

```dotenv
DRAGON_ENABLED=true
DRAGON_URL=https://dragon.example.internal
DRAGON_TOKEN=<bearer-token>
DRAGON_PIPELINE_ID=pl:default-security
DRAGON_REPOSITORY_ID=<идентификатор Go-репозитория вида u:...>
DRAGON_PUBLISH=true
DRAGON_PRIORITY=4
DRAGON_POLL_INTERVAL_SECONDS=5
DRAGON_TIMEOUT_SECONDS=1500
```

В `.env` двоеточие в `u:...` записывается буквально. В URL клиент кодирует
его автоматически как `%3A`. Последовательность `%a0` не является кодировкой
двоеточия и для этого идентификатора использоваться не должна.

HTTP-запрос повторяет подтверждённый `curl -F`: передаёт `Accept: */*`, Bearer
token, `multipart/form-data` с типом файла `application/x-zip-compressed` и
известным `Content-Length` без chunked transfer. Значения `name` и `label`
берутся из текущего Go-пакета, а не являются фиксированными тестовыми строками.

Если в контейнер передан `HTTPS_PROXY`, а Dragon доступен напрямую внутри
корпоративной сети, добавьте имя вашего хоста Dragon в
`NO_PROXY`. Ошибка Go-клиента вида `Post "...": Service Unavailable` означает,
что 503 получен при построении прокси-туннеля до получения HTTP-ответа Dragon.

Ответ `202 Accepted` содержит `id`, `run_url`, `status_url`, SHA-256 и сведения
о принятом архиве. Moder_repo проверяет, что возвращённый SHA-256 совпадает с
локальным, но даже несовпадение фиксируется только как ошибка информационного
шага и не останавливает публикацию.

## Получение результата

Клиент опрашивает `status_url` до терминального статуса:

- успешные: `success`, `succeeded`, `completed`, `passed`;
- неуспешные: `failed`, `error`, `cancelled`, `canceled`.

Из фактического ответа сохраняются pipeline, repository, stages, краткие
сведения о jobs, `oakshield_url` и статусы сканеров. Логи используются для
извлечения информационных счётчиков, но целиком в PostgreSQL не копируются.
В карточке показываются:

- явно указанные уязвимости Trivy;
- секреты Gitleaks (`leaks found`);
- находки Semgrep/Gosec (`Findings`).

Эти категории разделены намеренно: находка Semgrep или секрет не должны
автоматически называться уязвимостью. Если сканер не пишет счётчик в status
API, ноль означает только «счётчик не найден в доступных логах», а не
«пакет гарантированно чист».

## Настройки web

Все параметры Dragon доступны администратору в web-настройках. Токен хранится
как зашифрованный секрет и отображается маской. Изменения runtime-настроек
подхватываются процессами сервиса без пересборки образа.

| Переменная | Назначение |
|---|---|
| `DRAGON_ENABLED` | отправлять Go-архивы в Dragon |
| `DRAGON_URL` | корень API без `/docs` |
| `DRAGON_TOKEN` | Bearer PAT создания и чтения запусков |
| `DRAGON_PIPELINE_ID` | pipeline архивного запуска |
| `DRAGON_REPOSITORY_ID` | репозиторий Dragon, созданный для Go |
| `DRAGON_PUBLISH` | поле `publish` формы Dragon |
| `DRAGON_PRIORITY` | поле `priority` формы Dragon |
| `DRAGON_POLL_INTERVAL_SECONDS` | период опроса `status_url` |
| `DRAGON_TIMEOUT_SECONDS` | общий предел загрузки и ожидания |

## Ограничение текущей реализации

Polling пока удерживает один worker slot до завершения Dragon. При высокой
нагрузке следующий этап — сохранять `run_id/status_url` сразу после `202`,
освобождать worker и завершать информационный шаг отдельным poller или
callback. Это изменение влияет на пропускную способность, но не на решение о
публикации.
